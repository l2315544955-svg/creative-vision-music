# PoloAI 控制台核验记录（2026-03-24）

## 1. 核验范围

本记录基于 2026-03-24 对 `https://poloai.top/console` 的实际登录态核验，目标是确认：

1. 当前账号在控制台里能看到哪些模型
2. 当前账号在价格页里能拿到哪些按次计费模型
3. 当前账号是否已经显式开放 Suno 音乐模型与费用

说明：

- 本文不记录登录凭据
- 本文只保留项目决策需要的事实结论

---

## 2. 已核验接口

### 2.1 认证相关

- `GET /api/status`
- `POST /api/user/login?turnstile=`

核验结果：

- `turnstile_check=false`
- 登录不需要 Turnstile 验证
- 当前站点使用 session cookie 维持登录态

### 2.2 用户侧模型与分组

- `GET /api/user/models`
- `GET /api/user/self/groups`

核验结果：

- 这两个接口除了登录 cookie 外，还需要请求头 `New-Api-User`
- `New-Api-User` 的值就是当前登录用户 ID

### 2.3 定价接口

- `GET /api/pricing`

核验结果：

- 当前登录态可以直接读取
- 返回 498 条带定价的模型记录

### 3.2 当前账号可见分组

和本项目最相关的分组有：

- `AIGC（生图/视频/音乐）`，倍率 `1`
- `veo`，倍率 `1`
- `sora`，倍率 `1`

需要注意：

- 分组名里虽然写了“音乐”，但控制台当前实际暴露出来的是视频和生图能力
- 不能因为分组名字里出现“音乐”，就默认当前账号已开放 Suno 计费

## 5. 当前账号没有看到的内容

在 `/api/user/models` 与 `/api/pricing` 中都没有搜到以下音乐相关模型名：

- `suno`
- `chirp`
- `udio`
- `mureka`
- `music-2.5`

这意味着：

1. 当前账号在控制台里没有显式开放这些音乐模型
2. 当前价格页不能直接反推出 Suno 音乐的真实成本
3. Suno 文档能力与控制台显式定价，很可能分属两套可见性规则

## 6. 对项目的实际影响

### 6.1 可以继续推进的部分

1. 继续按 `poloapi.apifox.cn` 的 Suno 文档推进音乐站 MVP
2. 后端把音乐模型、扣点和售价做成后台可配置
3. 第一阶段只承诺 Suno 主工作流，不承诺多模型音乐工作台

### 6.2 当前不能硬写死的部分

1. Suno 单次真实采购成本
2. `chirp-v4` 是否对当前账号真实开放
3. `mureka / udio / music-2.5` 是否能通过同一账号购买或调用

### 6.3 商业与产品上的决策

第一阶段建议：

1. 产品侧做 “Suno create 核心工作流复刻”
2. 商业侧优先做余额不足即弹出充值窗口
3. 后台侧先支持人工配置模型成本、前台售价、扣点值

不建议第一阶段承诺：

1. 完全 1:1 多模型工作台
2. 所有音乐模型价格透明可查
3. 所有参考音频、歌手性别、多模型切换都真实生效

---

## 7. 后续补数需求

如果后续要把音乐模型成本表做成可直接运营的版本，还需要补其中任意一种材料：

1. 已开通音乐模型的 PoloAI 账号
2. 含 Suno 价格的后台截图
3. 供应商给出的采购价口径

在没有这一步之前，项目可以继续设计、开发和上线 MVP，但成本表必须保留后台配置项，不应写死。
