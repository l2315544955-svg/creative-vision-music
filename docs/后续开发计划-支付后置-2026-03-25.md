# 后续开发计划（支付后置版，2026-03-25）

## 1. 当前判断

支付后置仍然正确，但当前项目的优先级已经变化。

现在真正应该继续推进的，不再是“先把数据库、登录、任务落库补起来”，因为这些已经完成首版。下一步重点应该转到四条主线：

1. Suno 任务生命周期自动化
2. 个人版账户体系从开发态走向可上线态
3. 组织版一期能力落地
4. 后台运营与人工补单能力

## 2. 已完成到什么程度

当前已经完成：

1. 轻量登录和会话
2. SQLite 主数据层
3. 个人积分账户与流水
4. 生成前预检
5. 任务提交与作品落库
6. Suno 提交冻结、刷新结算
7. Minimax / Suno lyrics 正式扣减
8. 支付、订单、充值弹窗边界保留

因此后续计划必须建立在“个人版闭环已初步跑通”的前提上，而不是重复补基础设施。

## 3. 支付后置原则

后续阶段继续遵守以下边界：

1. 前端保留充值入口和支付结果页
2. 后端保留 `billing` / `payments` 边界
3. 不继续把开发资源投入到真实支付联调
4. 新能力不能依赖支付已完成
5. 订单可以先支持人工确认和后台补发积分

## 4. 建议的后续开发顺序

### 第一阶段：任务生命周期自动化

目标：从“用户手动刷新”升级为“系统自动追踪和结算”。

必须完成：

1. 增加后台任务轮询机制
   - 定时刷新 `SUBMITTED` / `NOT_START` / `RUNNING` 状态的 Suno 任务
   - 自动把远端结果回写到本地

2. 增加结算守护
   - 成功时自动把冻结积分转正式扣减
   - 失败时自动释放冻结积分
   - 异常任务留待人工介入

3. 增加任务状态治理
   - 统一超时状态
   - 记录最后一次同步时间
   - 记录失败原因与失败次数

4. 增加任务刷新策略
   - 首次提交后短间隔轮询
   - 稳定后退避重试
   - 达到阈值后进入人工处理队列

交付标准：

1. 用户不手动点刷新也能拿到 Suno 最终结果
2. 冻结积分不会长期悬挂
3. 任务状态可以自动推进到终态

### 第二阶段：个人版账户从开发态走向可上线态

目标：保留当前开发效率，同时把账户体系升级到可对外开放的形态。

必须完成：

1. 替换开发态登录
   - 手机号验证码，或
   - 邮箱验证码

2. 完善账户资料
   - 用户名
   - 手机号 / 邮箱
   - 状态字段
   - 风控和禁用状态预留

3. 补个人中心最小能力
   - 我的余额
   - 我的流水
   - 我的订单
   - 退出登录

4. 前端补可视化账单区块
   - 最近流水
   - 最近订单
   - 当前冻结中的任务说明

交付标准：

1. 非开发人员也能完成登录和进入创作台
2. 用户能看懂自己为什么被扣点或冻结
3. 会话和用户资料不再只服务于开发测试

### 第三阶段：组织版一期

目标：落地“公司负责人 + 成员账号”的首版组织模型。

必须完成：

1. 组织创建与成员关系
2. 成员邀请与加入
3. 组织积分池
4. 成员额度分配
5. 组织任务归属
6. 组织账本与订单归属

建议接口范围：

1. `POST /api/organizations`
2. `GET /api/organizations/current`
3. `POST /api/organizations/members`
4. `POST /api/organizations/credits/allocate`
5. `GET /api/organizations/tasks`
6. `GET /api/organizations/ledger`

交付标准：

1. 公司负责人可以创建组织并管理成员
2. 成员消费的是组织额度而非个人余额
3. 组织侧可查看任务与消耗

### 第四阶段：后台运营面和人工补单能力

目标：在支付仍后置的情况下，先把运营闭环补齐。

必须完成：

1. 人工充值确认台
2. 手工补发积分
3. 手工关闭异常订单
4. 用户检索和任务检索
5. 失败任务人工重试或标记
6. 账本与订单对账视图

交付标准：

1. 即使不接真实支付，也能让运营处理订单和额度
2. 异常任务和异常订单不需要直接查库处理

### 第五阶段：支付恢复

目标：等个人版和组织版业务稳定后，再恢复真实支付。

必须完成：

1. 支付宝参数配置
2. 异步通知稳定性验证
3. 订单到账与积分发放闭环
4. 支付成功后的幂等补单
5. 后台对账与异常处理

说明：

1. 这一阶段继续排在后面
2. 只有在账户、组织、运营链路稳定后才值得恢复

## 5. 建议拆成最近三个迭代

### 迭代一

聚焦：

1. Suno 自动轮询
2. 任务终态自动结算
3. 任务同步字段补齐
4. 最近流水前端展示

### 迭代二

聚焦：

1. 手机号或邮箱登录
2. 我的余额 / 流水 / 订单页
3. 人工充值确认后台最小版

### 迭代三

聚焦：

1. 组织创建
2. 成员管理
3. 额度分配
4. 组织任务视图

## 6. 当前最值得马上继续做的事

如果只选一个方向继续开发，优先做：

1. `Suno 自动轮询 + 自动结算`

原因很直接：

1. 现在个人版的主要体验缺口就在这里
2. 积分冻结已经实现，最需要的是自动从中间态走到终态
3. 这项能力会直接影响个人版和未来组织版
4. 它比支付恢复更接近主业务核心
