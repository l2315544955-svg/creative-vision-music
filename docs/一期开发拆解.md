# 一期开发拆解

## 1. 开发边界

本项目的一期目标不是做一个“什么都有的 AI 平台”，而是做一个能收费、能稳定生成、能快速交付的音乐站。

开发边界固定如下：

1. 新项目文件全部放在 `Creative Vision Music`
2. 不把新页面、新文档、新业务代码直接写进 `ruoyi`
3. 不让本项目在运行时依赖 `ruoyi`
4. 如需账号、组织、点数、聚合代理能力，只允许把 `ruoyi` 中可用代码复制到本项目后再调整优化
5. 第一期主路径以 Suno 为核心，但首版允许 `Suno + 海螺音乐` 两模型
6. 第三方供应商优先使用 `AIZNT`

## 2. 一期必须交付的东西

必须有：

4. 余额不足充值弹窗

### 2.2 后台管理侧

必须有：

1. 音乐模型配置
2. 单次扣点配置
3. 套餐/资源包配置
4. 订单管理
5. 组织账号与成员配点

可以延后：

1. 数据驾驶舱
2. 复杂运营位
3. 自动化营销体系

## 3. 创作页最小闭环

### 3.1 页面结构

第一页只做最核心的结构：

1. 左侧创作表单
2. 右侧最近作品/生成记录
3. 顶部模型与余额区
4. 余额不足时的充值弹窗

### 3.2 创作表单字段

必须有：

1. 模式切换
   - 灵感模式
   - 自定义模式

2. 文本字段
   - 标题
   - 风格标签
   - 歌词
   - 灵感描述

3. 开关项
   - 纯音乐

4. 模型项
   - `Suno`
   - `海螺音乐`

5. 续写项
   - 作品选择
   - 继续时间点 `continue_at`

6. 提交按钮

### 3.3 首版不做成真实能力的项

这些可以先保留 UI 占位或直接不开放：

1. 歌手性别精确控制
2. 参考音频上传
3. 更复杂的多模型音乐工作台
4. stems 分离前台入口

## 4. 最小接口契约

### 4.1 对第三方音乐能力的内部抽象

前台不要直接感知第三方接口细节，统一走项目自己的内部接口层。

建议抽成以下内部接口：

1. `POST /api/music/lyrics`
   - 输入：主题、风格、关键词
   - 输出：任务 ID

2. `POST /api/music/generate`
   - 输入：模式、标题、歌词、风格、纯音乐、续写参数
   - 输出：任务 ID

3. `GET /api/music/tasks/{taskId}`
   - 输出：状态、进度、作品结果、失败原因

4. `GET /api/music/works`
   - 输出：我的作品列表

5. `POST /api/billing/precheck`
   - 输出：是否余额足够、本次预计扣点、缺口

6. `POST /api/billing/create-order`
   - 输出：订单信息、支付跳转参数

### 4.2 以 `ruoyi` 为参考源码的独立实现方式

一期建议只把这些能力当作参考源码来源：

1. 登录与用户体系
2. 组织入组与成员管理
3. 点数管理
4. 模型扣费配置
5. 第三方代理能力

执行原则：

1. 不直接调用 `ruoyi` 的运行服务
2. 不在 `ruoyi` 目录内开发本项目功能
3. 只复制需要的代码、表结构和接口思路到本项目

不建议一期去做：

1. 深度改造 `ruoyi` 原有前台
2. 在 `ruoyi` 目录内直接开一个新音乐前端
3. 把音乐站的页面逻辑塞进已有业务模块

   - 提交参数快照

2. 音乐作品
   - 作品 ID
   - 所属任务

   - 音频地址
   - 封面地址
   - 时长
   - 是否可下载

3. 模型配置
   - 模型编码
   - 展示名
   - 是否启用
   - 成本
   - 售价
   - 扣点值

4. 充值套餐
   - 套餐名
   - 金额

   - 订单类型
   - 金额

   - 回调时间

## 6. 收费窗口的最短实现

### 6.1 唤起时机

以下时机都可以直接弹充值窗：

1. 点击生成时余额不足
2. 进入创作页时余额低于阈值
3. 续写前检测余额不足

### 6.2 弹窗内容

首版只保留 5 个元素：

1. 当前余额
2. 本次预计消耗
3. 三档资源包
4. 一个会员入口
5. 一个组织邀请码入口

### 6.3 套餐建议

首版建议直接写死三档测试套餐，后续再后台化：

1. 体验包：`9.9`
2. 标准包：`29.9`
3. 进阶包：`99`

会员可以先只做一个：

1. 月卡

## 8. 一期最大的两个风险

### 8.1 音乐模型成本未锁死

当前能确定：

1. AIZNT 已显式给出 `suno_music / suno_lyrics / music-1.5 / music-2.0` 定价
2. 但 Suno 的 `mv` 版本和计费 SKU 不是一一映射

所以一期必须：

1. 成本后台可配置
2. 前台售价后台可配置
3. 不写死任何 Suno 版本与价格绑定关系

### 8.2 目标页是多模型工作台

`suno.cn/create` 真实形态不是单一 Suno 页，而是多模型音乐工作台。

所以一期必须：

1. 复刻主流程和主要视觉结构
2. 不承诺所有模型都同步上线
3. 把模型切换设计成可扩展结构
